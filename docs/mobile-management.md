# 手机管理与商城切换

## 使用方式

首次使用，在管理后台「员工与权限」生成一次性绑定码，在小程序「我的 → 账户与设置 → 商家绑定」（页面下方，点开）填写。管理后台可用手机浏览器打开。已有绑定的微信无需重复绑定。

绑定后，首页和「我的」显示「商城 / 管理」切换。管理页也可直接切回商城。普通顾客、仅有分销资格的用户不显示管理切换。冷启动沿用商家工作台入口规则；从分享链接进入商品和订单仍按原来的链接打开。

整体沿用淡蓝色主题，管理页不增加第二套购物底栏。

## 已提供的日常操作

菜单共 11 个入口，按岗位权限显示（每行 4 个；超过 8 个时按钮自动变矮，320 宽度也不横向滚动）：店长 11 个，财务 9 个，客服 4 个，仓库 3 个，商品 2 个，发货和内容岗位各 1 个。

| 模块 | 手机可做的事 | 岗位权限 |
| --- | --- | --- |
| 订单发货 | 查看订单和收件信息、填写物流发货、备货、自提码核销；首页的今天/本月销售额和本月收款只给能看收款的岗位（管理/财务），仓库、发货、客服只看到待办数 | 订单、发货、自提权限分别校验 |
| 客户订单 | 按手机号、尾号、昵称、订单号或会员编号查客户和订单（手机号同时比对会员资料、收货地址、下单收货人和分销/企业申请里的号码）；客户详情、最近订单；订单详情可直接发货（单仓整单） | 管理/客服/财务；会员的余额、积分、佣金仅管理/财务（订单的付款构成三种岗位都能看，与电脑后台一致） |
| 售后处理 | 审核退款/退换/补发、查看凭证、延长寄回、登记收货、验收、补发物流 | 管理/财务可处理，客服可查看 |
| 客户审核 | 查看企业/分销申请及资料、通过或驳回 | 管理/客服 |
| 商品管理 | 查看商品、编辑现有商品名称/规格/零售价/说明、上下架 | 管理/商品岗位可编辑，仓库/内容岗位可查看 |
| 库存管理 | 查看分仓库存、库存流水、增减可售库存 | 管理/仓库可调整，商品/财务可查看 |
| 提现审核 | 金额和扣费明细、批准/拒绝、查询微信转账状态；微信没有受理或拒绝的转账，可「核实后关闭并退回」（系统先向微信再查一次，微信确认没有这笔转账才关闭并把金额退回可提现佣金，查到了就不关闭） | 管理/财务；本人申请不能由本人审核或关闭 |
| 收款报表 | 按日期查看各来源实收、退款、净收和收退明细 | 管理/财务 |
| 经营数据 | 今天/本月/自选（最多92天）的销售额、实收现金、退款、订单数、客单价、新客户；商品销量前10、分销业绩前10；佣金与提现；待办跳转 | 管理/财务 |
| 分销商 | 分销商列表（分页、搜索、筛选）、详情、登记加盟款（可附凭证图片）、作废、调拿货档位、单独佣金比例；本人记录不能自己改 | 查看与登记：管理/财务；作废、调档位、单独比例：仅管理 |
| 经营设置 | 提现规则（最低提现、手续费、代扣比例、处理时限、单笔最多到账）、分销商平台服务费、配送方式、运费金额、自提门店增删改 | 查看：管理/财务；修改：仅管理 |

本期集中于日常经营。以下仍在电脑后台操作：资格开通/关闭、冻结提现、充值开关、其它 9 项平台费用、新建商品、上传商品图、优惠券活动、员工权限、运费地区与件数、配送说明，以及复杂分仓拆单发货；没有声称手机端覆盖所有后台功能。

已知限制：电脑后台保存经营设置时没有版本核对，之后在电脑上保存会覆盖手机上的修改（两边都是整份保存）。手机上保存时会核对“改之前看到的值”，别人刚改过就拒绝并提示刷新。

## 接口与数据规则

- 新增固定的 `/shop/app/staff/manage/*` 接口，沿用 `X-Shop-Token`。每次请求重新验证微信会员绑定、在职员工状态和数据库中的当前权限。
- 服务端仅在当前请求中建立该员工的权限上下文，调用原有受保护后台方法，在成功和异常时均恢复上下文。没有向小程序签发后台登录令牌，也没有任意地址转发接口。
- 商品编辑在数据库事务中锁定商品并核对“打开编辑时看到的名称、规格、零售价、说明和上下架”（库存变动也会让商品版本加 1，只比版本会让卖得好的商品改不了价），只允许更改列明字段；库存、渠道、拿货价格配置等从当前记录保留。
- 库存沿用原 requestKey 和库存事务。响应中断时锁定表单，重试使用原始内容与原始单号。其余不确定的写入结果要求先刷新核对状态。
- 售后、提现沿用后台原状态流转、锁和支付/退款单号；原审计记录使用真实员工账号。手机接口另行阻止绑定会员审批自己的提现，且不开放模拟到账快捷操作。
- 申请资料与售后凭证通过鉴权接口加载。客户资料类型和文件名受限，不接受任意文件路径。
- 实收报表继续使用现有现金统计规则，余额消费不再次算现金收款；净收不是利润。
- 本次无需新增数据库表或迁移业务数据。
- 经营数据、分销商、经营设置、客户订单四个模块（2026-09-26 加入）：数字全部复用电脑后台“经营报表/现金实收”的算法，和电脑上同一时间段一致；登记加盟款带单号，结果不确定时只能原样重发（不会重复计入）；作废、调档位、单独比例和设置保存结果不确定时先重新读取核对；设置保存提交“改之前看到的值”，服务器核对后把允许修改的项合并进完整配置再调用原后台保存；调档位必须带明确的方式（自动/手动/停用）。客户订单查询每人每分钟最多 30 次。
- 代码位置：手机管理全部在 `pages/staff/`（分包）下。`services/staff-management.js` 已移到 `pages/staff/services/staff-management.js`，新增 `staff-dashboard.js`、`staff-distributors.js`、`staff-settings.js`、`staff-lookup.js`（纯函数、无 import，测试直接加载），组件在 `pages/staff/components/`，四个新模块共用样式 `pages/staff/styles/staff-module.css`。主包没有新增文件。

- 小程序 Node 测试：184 项通过，新增报表读取失败、翻页失败、查询日期一致性、迟到响应和不确定提交的回归检查。
- 本轮后端相关测试 41 项通过：手机管理及权限代理 11 项，加上隔离本地 MySQL 测试 30 项（手机管理写入 4、工作台及员工绑定 3、微信提现 18、现金统计 1、微信支付与退款 4）。支付网关使用测试替身，没有产生真实资金交易。
- H5 与微信小程序编译成功；微信构建使用正式 API 配置。
- 浏览器使用本地模拟接口验证七个入口、价格编辑、库存调整、资格审核、退款审核、提现审核/查询、现金报表、商城切换、岗位隔离，以及 320/390/430/1280 宽度。
- 另外验证库存响应丢失后重试、双击只发送一次、结果不确定时表单锁定、退货收货→验收→换货补发，及矮屏首页按钮不被底栏遮挡。
- 补查自提备货、错误自提码拒绝、正确核销与双击；申请资料鉴权预览、企业审核和分销驳回、退货地址校验、延长寄回、补发审核、权限撤销和登录过期。
- 模拟预览仅用于展示，未产生真实订单、退款或转账。没有对生产微信支付进行端到端验证。

本轮修复：现金查询失败不再显示假零值，翻页失败不改变已显示页码，已显示数据对应的日期单独标明；补全提现状态和库存流水方向，停用仓库不显示调整按钮；非库存操作结果未确认时，在按钮和提交方法两处禁止重发；图片请求返回时复核登录身份；手机商品保存与原后台使用相同的数据库加锁顺序。

旧临时数据库有表文件缺失，本轮使用新建的本地隔离实例与种子数据，按当前启动迁移补齐测试字段后验证。数据库测试记录回滚或清理，并检查未遗留测试会员；生产数据库未参与。

## 上线状态

四个新模块只完成了本地代码、测试和构建，未部署服务器、未上传体验版。它们依赖后端新增的 `/shop/app/staff/manage/dashboard|distributors|settings|lookup` 接口和员工新权限标志，「核实后关闭并退回」依赖后端提现改动，都必须先发布后端，再上传对应小程序包；不能只上传前端就声称正式可用。首次上线后仍需用已绑定员工的真机账号核对岗位、读取真实数据和页面切换，并在电脑后台选同样日期核对经营数据。

本地模拟预览脚本及结果在 `.local/mobile-management-qa/`（`check.cjs`、`retry4.cjs` 等），不会进入小程序发布包。
